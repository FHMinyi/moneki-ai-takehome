# G2-01：维护者重建后获得完整、最新且计数真实的知识库

**状态：** 已发布 [#13](https://github.com/FHMinyi/moneki-ai-takehome/issues/13)，未启动实现。

## What to build

维护者使用已有重建命令并重启服务后，Markdown、TXT、HTML 中的实际知识文档完整进入索引；新旧文档变动能反映在检索结果中，健康接口如实报告当前索引。范围对应诊断 D01、D02、D03、D09、D10。

## Acceptance criteria

- [ ] 对原始知识库按实际文件身份加载35篇知识文档，包含英文邮件、HTML FAQ 和 GBK 通知；说明文件不计入。数量从实际索引计算，不能写死35；文件名前缀定义 doc_id，格式不改变身份。
- [ ] UTF-8 和本包实际 GBK 内容正确解码，关键中文不被静默吞掉；HTML 可见正文保留段落及实体含义，script/style 不进入可引用正文。保存至少一条 GBK 与一条 HTML 原文对照证据。
- [ ] 用隔离小知识库经真实重建、服务启动和 `/api/retrieve` 验证 TXT/HTML 材料确实可达；用明确词项或唯一标记验证摄取，不提前要求自然问句排名。不得仅靠调用 loader 的单测证明整链路可用。
- [ ] 对隔离知识库分别新增、修改、删除材料以及切换 KB_DIR，使用公开重建命令并重启后，健康计数、索引内容和检索结果更新；新增可查、修改不返回旧事实、删除不残留，换目录不串库。相关别名与元数据随材料同步更新。
- [ ] 同一输入重复重建结果稳定；无旧缓存的首次启动和有旧索引的升级重建均可用，不能要求评审手动删缓存。测试不得污染共享工作树的运行产物。
- [ ] `/api/health.kb_docs` 等于实际进入索引的文档数，`kb_chunks` 等于实际片段数；空知识库如实返回零并允许启动，不虚报35或目录文件数。
- [ ] 本项失败探针先红后绿；原有后端检查及公开 metrics/data 结果保持通过。自然语言检索和问答尚未完成的失败如实报告，不作为本项已修复成果。

## Blocked by

无。执行需另行获准；以前一关应用提交与已保存诊断为参考固定点，实际开工记录届时 main。

## Scope and delivery

保留 starter 与既有技术方向，沿用重建后重启；本项不引入热更新、向量服务或付费调用，不修改数据口径、混合问答、会话或 UI。不得硬编码答案或更改公开评分器。

按任务书更新 DEBUG_LOG.md，记录真实实验、根因位置、红灯、修复提交及绿灯。交付 SPEC EXECUTION RECEIPT，逐项列证据、提交、局限和资源清单；保护已有未提交文件，提交/PR/清理仅在执行授权内完成。
