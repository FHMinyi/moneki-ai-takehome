# G2-02：运营检索到完整且来源一致的证据片段

**状态：** 已发布 [#14](https://github.com/FHMinyi/moneki-ai-takehome/issues/14)，未启动实现。

## What to build

运营通过现有检索接口查看证据时，文档末尾的重要事实不会消失，表格行和标题有必要的理解上下文，每条结果的正文、文档编号和片段编号都能追溯到同一来源。范围对应诊断 D04、D06。

## Acceptance criteria

- [ ] 短文档、恰好一个/多个分块边界、边界前后一个字符及最后一段均完整覆盖；实际知识库逐篇审计无未覆盖正文。允许 overlap，不以“直接拼接必须等于原文”锁死实现。
- [ ] 段落与表格策略至少用一份含尾段事实的文档和一份多行表格证明：返回片段可找到所需事实，行内容有可追溯的表头/标题上下文，不把不同文档的文字拼成事实。
- [ ] 通过真实 `/api/retrieve` 验证 doc_id、chunk_id、text 和内部元数据始终对应同一来源；对当前错位样本及刻意包含同文档多个高分片段的夹具，重排、去重、补位均不改变归属。
- [ ] 区分检索用上下文和可引用原文。即便检索文本补充标题/表头，引用仍能回到对应文档的一段连续可见正文；不能把合成上下文当原文 quote。
- [ ] 重复构建同一输入时片段身份与排序可复现；改变分块规则后不继续加载旧布局缓存。按当前实际片段数报告健康状态，不硬编码72等旧值。
- [ ] 使用真实材料和独立夹具保存修复前红灯、修复后绿灯与 HTTP 响应。G2-01 的格式、编码、增删改和换目录验证保持通过。

## Scope and delivery

本项完成完整性与来源可信性，不要求提前修通自然语言排名或聊天；可用明确词项驱动真实检索。保留接口契约和公开题库，不修改第一关口径、不调用付费模型、不新增 UI。

更新 DEBUG_LOG.md 并按缺陷保留先红后绿提交证据。交付 SPEC EXECUTION RECEIPT，逐项对应验证结果、提交、剩余缺陷和工作树/分支/服务/产物清单；已有未提交材料保持不变。
