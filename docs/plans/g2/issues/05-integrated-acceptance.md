## What to build

评审按已记录的启动、重建与评测步骤，在没有 Key 的情况下复现可靠检索和单轮文档问答；更换知识库后，服务使用新材料作答。交付报告清晰区分原始基线、第二关起点、第二关结果和第三关尚未完成项。

## Acceptance criteria

- [ ] 在明确记录提交的干净源码副本中安装依赖并使用现有三步入口启动，无预生成索引或本地运行产物依赖。明确禁用真实模型配置，记录环境、命令、实际提交及产物；不要声称在未测试的平台上通过。
- [ ] 使用未修改的55题公开题库跑全量评测，保存原始 JSON/Markdown 输出。metrics 6题、data 6题、retrieval 15题、doc 8题、V01/V02及health均通过；其他题真实报告，不能删题或把部分轮次通过算整题通过。
- [ ] 历史政策的独立完整问句验证通过；V03 第二轮、多轮及混合能力仍依公开结果分流，不通过时明确标注为第三关待办，不伪造第二关满分。
- [ ] 知识库替换验证经真实重建、重启、HTTP 检索和聊天覆盖新增、修改、删除、目录切换，以及格式/编码、事实与别名变化；期望值独立来自替换材料，确认新事实生效、旧内容淘汰、来源和引用正确，不能仅比较缓存键。
- [ ] 汇总原有后端与新增真实 RAG 回归，逐项核对十类启动诊断缺陷及实施中新发现缺陷；允许合理调整诊断探针以适配 overlap 等设计，但行为保证不能消失，不能用 xfail/mock/删断言取得绿灯。
- [ ] 已有第一关浏览器验证与指标/纯数据题保持通过，看板可正常筛选和展示；保存输入及已有未提交材料的保护证据，数据源没有被修改。
- [ ] EVAL_REPORT.md 并列保留原始无模型17/100、原始真实模型25.5/100、第二关起点41/100及本次实际结果，附命令、提交、模式与关键配置；不得将本次无模型结果称为真实模型最终分数。
- [ ] DEBUG_LOG.md 满足每个缺陷的现象、假设、验证、根因、修复提交、回归红绿证据要求；AI_USAGE.md 如实记录本阶段工具与判断，README 只更新实际需要的启动/重建/选型说明。不得补写未发生的人工判断或实验。
- [ ] 形成明确移交清单：已验证剩余失败、仅代码风险、尚未验证能力分别列明；阻塞第二关目标的共享文档证据问题回到原任务修正，不以“第三关待办”掩盖未完成验收。
