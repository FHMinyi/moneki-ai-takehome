# G2-04：运营通过单轮问答获得正确文档事实与真实引用

**状态：** 已发布 [#16](https://github.com/FHMinyi/moneki-ai-takehome/issues/16)，未启动实现。

## What to build

落实用户已确认的 A 方案：运营向现有 `/api/chat` 提出完整的制度、通知或历史政策问题，得到相关事实及适用版本的真实原文引用；不能再把退款政策等文档问题回答成全量经营汇总。本项以无模型模式交付。

## Acceptance criteria

- [ ] 在明确未配置 Key 的真实服务上，未修改公开题库的 C01—C08、V01、V02 全部通过，包括响应类型、事实、引用、禁用旧版本、逐字核对、trace 及契约上限检查。
- [ ] 纯文档问题使用正确的问答路由和事实来源，不因“退款”“现在”“多少”等词误转成无关经营汇总，也不因当前日期超出销售数据范围而拒答仍有材料支持的政策问题。
- [ ] 用明确日期的完整问句验证历史政策及新旧版本边界；当前与历史答案分别引用适用版本。公开 V03 保持原样运行和报告，单轮补充题通过不记成其第二轮追问或整题通过。
- [ ] 每项文档事实有对应 doc_id 与原文连续 quote，符合规范化后400字符、最多4份引用等契约要求；HTML、GBK、表格和文档尾段至少各有一条整链路证据，不能跨段拼接、改字或借用另一篇文档编号。
- [ ] 材料没有支持的事实不编造：加入与现有文档主题接近但缺少答案的单轮问题，检查诚实说明与引用证据相符；零分补位、无关段落和文档内指令不能被当成答案依据。
- [ ] 不同问法与替换文档事实后，经重建重启得到相应新答案；代码不写死题号、事实数值或文档内容。不把提高 mock 分数变成专门匹配公开题的模板分支。
- [ ] 每个回答的 trace 可取回，并能核对文档问题路由、实际检索和取证过程；修复路径发生异常时遵守聊天接口返回合法响应的契约，并保留可诊断原因。
- [ ] G2-01—03 相关回归、公开 metrics/data 及已通过的 refusal 题保持通过；全量评测中其他类别的变化如实列出，不能用文档题得分上涨掩盖已有行为退化。

## Scope and delivery

允许为单轮文档回答修复必要的规划、事实排序、引用生成及共用错误记录；先建立具体失败路径再修。混合查数、多轮继承、会话隔离、聊天前端、真实模型接入与完整安全对抗验收留到第三关。本项不加载 `.env.live`、不付费调用、不部署。

按任务书逐项更新 DEBUG_LOG.md，补充真实红灯/修复/绿灯证据。交付 SPEC EXECUTION RECEIPT，列出公开题、补充题、替换材料的结果，未通过及移交项、提交与资源清单。
