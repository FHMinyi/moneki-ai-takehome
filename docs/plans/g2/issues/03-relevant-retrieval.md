# G2-03：运营用自然问法检索到相关且适用的资料

> **发布时快照（2026-09-27）**：本文件保留发布时的任务规格，不同步后续执行状态。当前规格、依赖、验收进度与修正以 [GitHub Issue #15](https://github.com/FHMinyi/moneki-ai-takehome/issues/15) 为准。下文“未启动实现”等状态及授权描述均为发布当时记录。

**发布时状态：** 已发布 [#15](https://github.com/FHMinyi/moneki-ai-takehome/issues/15)，未启动实现。

## What to build

运营用中文、中英混合或真实商品/门店别名提问，检索接口能找到相关资料，并根据问题的时间和适用范围选择材料；历史问题能取得当时有效版本。范围对应诊断 D05、D07、D08及剩余真实检索失败。

## Acceptance criteria

- [ ] 未修改的公开检索题 R01—R15 全部通过。每题至少有符合 gold_all/gold_any 要求的真实相关命中，不得仅靠零分补位碰中目标文档；同时核验来源归属和内容支持关系。
- [ ] 追加确定性的不同问法验证，至少覆盖中文无空格问句、中英商品名/别名、标点与全半角变化、门店名称/编号变化；期望值来自实际材料，不能只复制公开问句或在产品逻辑中按题目分支。
- [ ] 现行查询排除已被替代的旧版本；明确历史日期能使用当时有效版本，新版生效前一天及当天边界正确。元数据字段在摄取、索引、检索及调用方间含义一致。
- [ ] 门店显式适用范围能约束候选，正文偶然提及门店不能误变硬过滤。使用两文档最小夹具及真实材料证明：有符合条件的候选时，不因先截断再过滤造成漏项。
- [ ] `/api/retrieve` 对合法 top_k 遵守契约数量和相关性降序要求，包括超过总片段数的情况；有适用候选时先完成适用性筛选再选结果。为满足接口数量保留的补位结果不能被问答链路当成有效事实证据。
- [ ] 检索接口与问答使用同一套检索实现；查询改写、词项/别名、候选分数及过滤原因可在测试证据或现有 trace 中核对。不能只为公开检索接口另做答案通道。
- [ ] 更换材料中的事实和别名后重建，结果跟随新内容，不依赖旧文档编号、词典常量或公开答案；保留无相关资料查询的可识别信号，避免所有查询都被当作有效命中。
- [ ] G2-01/02 行为回归及第一关 metrics/data 题保持通过；保存各相关缺陷先红后绿的真实检索证据。

## Scope and delivery

在现有 BM25 方向上通过实际语料对照选择中文词项方案；分词库、分块参数及权重是可逆实现细节，不新增外部检索服务或付费组件。发现材料冲突时按现有规则处理，不重新定义业务口径。历史问题使用完整问句，多轮继承留到第三关。

更新 DEBUG_LOG.md，记录采取及排除方案的实际结果，不编造比较实验。交付 SPEC EXECUTION RECEIPT、逐题和变体证据、提交与资源清单，保留剩余回答层问题供后续任务。
