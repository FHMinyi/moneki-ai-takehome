## What to build

运营询问“实际卖了多少、是否达标”或“为什么出现异常”，系统组合数据库实绩和适用文档，展示精确结论、数据证据与原文。只能查到现象但没有原因材料时，仍给出已证实的数字，并明确原因未知。

## Acceptance criteria

- [ ] 从用户问题经过模型工具选择、真实数据库/检索到回答与前端证据展示，覆盖实绩对目标、经营异常解释、支付占比解释、当前价格与建档价差异；原 H01—H06 对应行为均有验收条目，不只修第二关失败的 H01/H06。
- [ ] 实绩采用 KB-001 口径，目标/制度取适用文档；达标判断、差额、占比和区间比较由代码计算并渲染，记录操作数来源及计算关系。不能因为两个数字都在允许集合中，就接受错用指标或倒置比较方向。
- [ ] 数据与资料数值冲突按既定口径处理，不覆盖数据库实绩，不把文档中的估算当作查询结果。用独立替换数据和目标跨过达标边界，证明结论随输入改变而非命中公开题模板。
- [ ] “有零营业额但没有原因材料”的问题返回真实零值及查询证据，明确未找到原因，不塞无关引用；有原因材料时引用须匹配对应门店/商品/事件日期。区分材料记载与推断，不能凭销量波动编造因果。
- [ ] 组合 G3-02 的证据身份、适用范围和引用约定；答案中每个数据库数字及文档事实均可追溯。经营查询时间与政策/事件适用时间按问题含义处理，不能用同一个默认时间覆盖所有证据。
- [ ] 浏览器实际发送代表性混合问题，能在同一回答核对结论、查询条件/结果及引用；回答和证据符合 API 全部大小/数量约束，超过预算时选择相关证据或诚实拒答，不截断成无效 JSON 或丢失依据。
- [ ] 受控模型验证工具顺序变化、多次检索、无关结果和错误候选，业务结果仍正确；无 Key 已有通过题/轮次和 G3-01/02 保证不回退。真实模型验证按授权计划执行并保存全部尝试，未执行明确待验。
