# G3-06：运营引用每日趋势的范围向经营助手提问

## What to build

运营看到每日趋势有疑问，点击“加入提问”，在经营助手输入框看到一张明确说明日期、门店和指标的引用卡片，可以删除或替换，再输入问题并主动发送。系统使用该范围理解问题，重新调用业务工具获取真实数据，回答附查询证据。普通提问与引用提问共用同一问答流程。

## Acceptance criteria

- [ ] 在已成功加载的每日趋势上提供“加入提问”，打开已有聊天侧栏并附上整块趋势当前生效范围。卡片显示来源类型、起止日期、门店（含全部门店）和指标；不从尚未应用的筛选草稿取值，也不把默认选中的最后一天当成用户指定的分析日期。加载中、错误状态或响应与筛选不一致时不能附加。
- [ ] 每次最多一张引用卡片，可删除、替换；点击加入不自动发送、不自动触发模型。加入时固定范围，后续筛选变化不修改待发卡片或已发消息。发送后卡片保留在对应用户消息，待发区清空；重试使用原问题和原引用，新会话不携带旧引用，迟到响应不污染新会话。
- [ ] 增加有明确结构、白名单类型及字段验证的可选上下文输入，保持原 session_id/question 请求兼容。不接受任意工具名、SQL、指令或客户端金额作为执行依据；非法引用不被静默当成全量查询。参数错误仍遵守 chat 的 HTTP 200 和合法响应约定。
- [ ] 将用户原始问题与引用分别保留，经统一流程确定有效条件。文字中明确的新日期/门店等优先于引用，记录覆盖来源并在回答/证据中展示实际范围；“这一周”等无法唯一确定的指代要澄清，不能擅选最低一周或默认最后一天。此票验证单轮明确提问、覆盖与澄清行为，后续多轮澄清由最终集成验收。
- [ ] 后端校验条件并重新调用允许的业务工具，数字仍由代码计算/渲染，生成真实 data_evidence；不能把前端传来的数值或卡片文字变成权威证据。独立修改数据库、重建后以同一引用范围提问，结果跟随新数据。界面说明按本次重新查询结果回答，不承诺保留看板旧数值快照。
- [ ] trace 记录原始问题、原始引用、验证结果、最终条件与来源、覆盖/澄清依据及实际工具参数/结果，并留存可重放的请求。固定测试数据与受控模型重放时，有效条件和查询证据一致；不能只记录拼接后的最终提示词。不新增历史数据存储或第四关调试面板，也不承诺真实模型逐字可复现。
- [ ] 使用真实浏览器、后端和数据库，在 1280/1440/390 验证加入、删除/替换、筛选变化、主动发送、错误重试与新会话隔离。受控模型只控制模型行为，业务结果由实际工具提供；用独立期望核对请求中的引用和回答证据。普通无引用聊天、第一关图表选日和筛选行为不回退。
- [ ] 保存至少一条从“选定趋势→附加→提问→查询→答案→trace”完整的可复现证据，并分清受控模型与真实模型待验/已验结果。已有前两关保证保持，不新增“无 Key 必须完成所有含糊引用问法”的要求；真实调用使用总草案待批额度，不因新增功能自动获得付费授权。

## Scope and delivery

用户已确认单个“每日趋势”引用，不做通用附件系统、文件上传、截图/多模态识别、圈选区间、单点引用、多附件、历史快照或自动图表联动。引用是显式输入，既不是隐式读取整个看板，也不是永久绑定会话的筛选。

不另造问答引擎；沿用已有工具与证据约定。与其他票共同修改消息/会话/接口时，后合并的原执行会话同步最新 main 并补跑验证。必要的上下文留痕与重放随本票完成，第四关只需展示已有记录。
