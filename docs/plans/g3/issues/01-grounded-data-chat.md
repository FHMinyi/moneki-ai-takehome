# G3-01：运营在看板中查数并展开真实数据证据

**发布时状态：** 已发布 [G3-01 / #24](https://github.com/FHMinyi/moneki-ai-takehome/issues/24)，规格已确认，尚未启动实施；真实模型付费调用待单独授权。

## What to build

运营打开聊天侧栏，输入一个完整经营问题，模型选择已验证业务工具，系统从真实数据库取数并用代码渲染精确数字。用户能展开查询条件与结果；失败时看到明确说明并可重试。以这一条完整路径贯通启动、工具边界、trace 与前端，而非只交付基础设施。

## Acceptance criteria

- [ ] 无 Key 启动仍可用；按说明配置模型后 health 如实显示 live，请求使用指定地址、模型和 Key，不改业务代码即可切换。无启动探测付费请求，Key 不出现在源码、浏览器或留存日志中；补齐 LLM_SETUP 初稿。
- [ ] 模型只看到允许的业务工具与知识库检索；执行入口拒绝 run_sql、写操作工具、未知工具及非法参数。验证伪造/未声明工具调用不会执行查询副作用。数据库原有只读保证保留，不把移除工具描述当作完成。
- [ ] 在真实数据库与真实 HTTP 链路上，受控模型提出单区间查数和区间比较调用；答案金额、数量、比例及派生差值由代码基于结果计算/渲染，证据包含实际参数与结果。仅出现在问题、工具参数或其他结果字段中的数字不能冒充对应指标。用独立手算与替换数据证明没有固定答案。
- [ ] 正常且有数据依据的问题不会仅因旧规则规划误判而在进入 live 前被拒绝；越界、歧义、安全请求仍按契约处理，不为了进入模型而移除安全边界。
- [ ] 完成免费接入预检，符合契约 7.2/7.3，包括多轮工具消息、思考字段回传、畸形参数、错误码、空内容和超时；所有错误返回 HTTP 200 与合法 refusal，在总预算内结束，重试有界且计入剩余预算。适用项全部通过，非适用/未检查项说明理由。
- [ ] 每次 trace 可取到实际工具参数与结果、完整模型请求（含工具定义和各轮消息）、原始响应、耗时和真实错误；不得仅保留截断预览。诊断记录排除凭证，前端回答与证据不显示模型思考内容。
- [ ] 现有 React/TypeScript/Ant Design 看板中提供聊天侧栏、发送、等待、失败重试、新建对话及可展开数据证据。输入和长证据在 1280/1440/390 可用；聊天不隐式继承或修改看板筛选，用户主动引用每日趋势另由 G3-06 交付，不扩大本票首个查数闭环。等待时不重复提交，新建对话后旧请求结果不得写入新会话。
- [ ] 从第一条聊天开始按 session_id 隔离历史；两个交错会话的历史不互见。此票不声称已完成追问继承；缺少上下文的短问按契约澄清。浏览器用真实服务及受控模型验证实际请求/响应与证据一致，不用固定页面截图代替链路验证。
- [ ] 前两关相关回归保持；新增缺陷有真实失败与修复后证据。真实模型小样本未获授权时标为待验，不能把接入预检通过写成真实模型答对。
