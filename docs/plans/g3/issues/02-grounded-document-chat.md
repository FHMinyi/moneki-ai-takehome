## What to build

运营在聊天中提出完整的制度或历史政策问题，回答采用适用版本，并可展开真正支持该事实的原文。模型、现有纯文档回答和后续混合回答共享明确的证据身份与适用范围，不再在模型回答后随意从整篇文档补一条看似相关的引用。

## Acceptance criteria

- [ ] 用实际检索结果建立本次可引用证据集合，保留文档/片段身份、原文位置及适用范围。零分补位、被过滤版本和未检索到的其他文档不能因模型点名而成为引用；共享证据约定可以被后续混合回答复用。
- [ ] 文档陈述与证据显式对应，支持相应主体与属性；quote 来自真实连续文字，遵守规范化后长度与数量限制。覆盖表格、局部标题、无标题正文、HTML、GBK，不以逐字存在代替“确实支持结论”。
- [ ] 受控模型驱动真实检索与 chat，验证当前政策、明确日期的历史政策以及不在销售数据区间但有政策材料的问题。代码执行版本和门店适用约束，不依靠提示词提醒；原 C01—C08、V01/V02 对应行为列入检查，真实模型能力另列待验或实际结果。
- [ ] 注入“存在真实引用但不支持所述主体/属性”“引用文档其他段落的数字”“无关文档编号”的模型输出，系统不能交付该错误陈述；至少用第二关三类近主题误答和新的非固定问法验证。不能把整个 mock 规则回答器作为 live 的普遍否决条件。
- [ ] 资料中的恶意指令不被执行，合法业务事实仍可回答；真实检索包含注入文字时，受控模型与执行入口验证工具边界。原安全题相关行为保持，不能因文档含攻击文字就一律丢弃全部业务事实。
- [ ] 聊天回答的引用可展开查看文档标识和支持事实的原文；如果显示标题/元信息必须来自实际来源。未知证据字段有合理兼容，窄屏可读；浏览器验证展示内容与真实 chat 响应一致，不要求新增全文文档浏览 API。
- [ ] 修改独立文档事实与版本、重建重启后，新问答使用新材料；旧内容不残留。原第二关检索、单轮文档及标题身份保证保持，完整 trace 可核对检索/过滤/取证/模型往返，补充相关 DEBUG_LOG。
